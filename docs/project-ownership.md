# 故障智巡：项目能力归属与架构

故障智巡（AI Incident Response Agent）是以 Incident 为中心的故障调查与模拟处置系统。本文区分仓库导入的 MiniClaw 基础、在其接入点上的扩展，以及本仓库新增的 Incident 业务实现。这里的“本项目”表示**此仓库相对导入基线的增量**，不单凭 Git 作者或仓库归属推断某个人独立编写了全部代码。

## 审计口径

- `0992949` 是本仓库无父提交的 MiniClaw 开发基线；比较 `git diff 0992949..c89de7c` 与当前源码，判断文件是基线已有、被改动，还是后续新增。仓库配置的 `upstream` 地址在本次核验时返回 `Repository not found`，因此本文**不声称已与上游最新版本逐文件对比**。
- **Upstream**：导入基线已有，相关实现未因 Incident 业务改动；包含基线调用的 Pi 依赖能力。
- **Extended**：基线已有的接入点被本项目改动，或基线机制被新的 Incident 场景配置使用。它不表示本项目发明了基础机制。
- **Project-owned**：导入基线中不存在、由后续 Incident 提交新增的领域模型、工具、策略、事件或验收材料。它不表示已连接真实生产系统。
- 关键增量提交包括 `cbe1e7d`（模型）、`4bb779f`（Fixture 取证工具）、`611046b`（审批）、`0bea605`（事件与回放）、`1bd77ba`（评测）。

## Architecture：Incident Response System

```text
Incident Response System（故障智巡）
├─ Incident Domain          Incident / Evidence / Diagnosis 模型与状态
├─ Investigation Layer      取证 ToolCall、EvidenceGateway、调查流程
├─ Evidence Layer           Fixture Loader、四个只读查询、证据收集
├─ Diagnosis                证据引用校验、诊断或人工升级
├─ Policy / Approval        SAFE / ASK / BLOCK、宿主审批门、模拟处置
├─ Event / Trace            Incident AgentEvent、追加式 JSONL
├─ Replay                   只读时间线与状态重建
├─ Evaluation               12 个模拟案例、独立答案、确定性测试
└─ Agent Runtime
   └─ MiniClaw-derived runtime
      └─ Pi Agent Runtime、Provider、Session、Context、MCP Tool Calling
```

以上是**责任分层**，不是声称所有层已有独立在线服务或 Web 页面。当前 Incident 主链由 `incident_agent/`、Runner 的 `incident-*` 模块、受限 Demo、测试以及 Console 的薄 API/展示层构成；通用工作台仍保留用于配置兼容，独立 Incident Console 已接入。诊断建议不等于处置完成；审批通过后的 Executor 当前也只做模拟动作。Ground Truth 仅供 Evaluation 使用，不进入 Agent 工具结果或提示词。
