# v0.3.0 第 2 步：告警接入与查询

> 阶段历史说明：本文保留该步实施时的职责与命令；后续已串联为 v0.3.0 当前链路，最新状态及失败项以[第 8 步审查](v0.3.0-review.md)为准。

本步已实现协议接收、校验、脱敏、SQLite 持久化和聚合查询。不会创建调查任务、调用模型、运行取证工具、执行处置或发通知。现场 Provider、Runbook、任务和 Console 现场页分别属于后续步骤。原 Console 与 Fixture API 保留。实际验收结果见 [升级进度](v0.3.0-progress.md)。

## 认证与权限

新增权限 `ingest_alerts`，通过现有用户管理分配；普通成员和现有运维模板不会自动获得它。管理员沿用既有全权限规则。告警接口不匿名开放。

- Cookie：复用现有签名 Session、账户状态、强制改密码和权限校验。管理员可接入/查询全部来源；有权限的成员只可使用其有效机器凭据赋予的范围。
- Bearer：管理员 Cookie 签发；绑定现有有权限、有效且无需强制改密码的账户，限定一个 `source` 和精确的 `service/environment` 对，最多 32 对。最长有效期 30 天，数据库只存令牌哈希，明文仅创建响应一次返回；可撤销。每次请求重新检查所属账户状态和权限。
- Bearer 只在 `/api/incident-alerts` 中生效，即使归属管理员也不能签发/撤销凭据，更不能访问 `/api/admin`、系统配置、原 Console 审批等管理入口。携带无效 Authorization 时不降级使用 Cookie。
- 查询按凭据所属账户＋source＋服务＋环境隔离。越权详情返回 404；分页最大 100 条，offset 最大 10000。返回 `Cache-Control: no-store`。

## 接口

均位于现有 Web 服务，无新服务端口。下列路径带完整前缀：

| 方法 | 路径                                          | 用途                                            |
| ---- | --------------------------------------------- | ----------------------------------------------- |
| POST | `/api/incident-alerts/credentials`            | 管理员 Cookie 创建专用凭据                      |
| POST | `/api/incident-alerts/credentials/:id/revoke` | 管理员 Cookie 撤销凭据                          |
| POST | `/api/incident-alerts/webhook`                | 通用 JSON 告警，首次成功 201，重复 200          |
| POST | `/api/incident-alerts/alertmanager`           | Alertmanager v4 Webhook 批量，整体提交/回滚     |
| GET  | `/api/incident-alerts`                        | 告警 occurrence 列表                            |
| GET  | `/api/incident-alerts/incidents`              | 聚合 Incident 列表                              |
| GET  | `/api/incident-alerts/incidents/:id`          | 四字段 Incident＋独立 metadata＋最多 100 条告警 |

查询可带 `source/service/environment/limit/offset`。不支持任意 SQL/URL/文件路径。错误只返回稳定代码：输入或查询无效 400，未认证 401，权限/范围不足 403，找不到 404，幂等冲突 409，超出请求大小 413，存储不可用 503；不返回输入片段或原始数据库异常。

POST 要求 `application/json`；按实际流字节限制为 256 KiB（含 chunked 和虚报 Content-Length）。通用入口拒绝未知顶层字段；批量最大 50 个 alert，每个 labels/annotations 最多 64 项。调用者应处理失败并有界重试，接收端不做外部通知或无限重试。

## 统一模型与脱敏

通用入口必填 `source/service/environment/severity/starts_at/status/summary`，可填 `external_id/alert_type/fingerprint/ends_at/description/labels`。source、service、environment、fingerprint 必须是 1—100 字符的字母数字及 `._:-`，大小写保留，精确比较。

统一持久化：`source/external_id/service/environment/severity/alert_type/fingerprint/starts_at/ends_at/status/source_summary`，另存 `severity_raw/severity_mapping_status/alert_type_raw`、接收时间和 occurrence ID。时间归一到 UTC；开始时间不能超过接收时刻 5 分钟；结束不能早于开始，resolved 必须有有效结束且不得超出未来 5 分钟。firing 可无结束；Alertmanager 的 `0001-01-01…` 结束哨兵转 null。

| 外部级别（忽略大小写）                   | 内部优先级                                            |
| ---------------------------------------- | ----------------------------------------------------- |
| P0、sev0、0、emergency、blocker          | P0                                                    |
| P1、sev1、1、critical、fatal、high、page | P1                                                    |
| P2、sev2、2、warning、warn、medium       | P2                                                    |
| P3、sev3、3、info、informational、low    | P3                                                    |
| 其他或缺失的 AM 级别                     | null，`severity_mapping_status=unknown`，保留脱敏 raw |

`alert_type` 已知 PROBLEM/BUSINESS/EVENT/HOST（忽略大小写）；未知转 UNKNOWN 并保留脱敏 raw。Incident 汇总显示已知告警中最高优先级，同时单列 `unknown_severity_count`；null/未知绝不视为 P3。**P0—P3 是告警优先级，SAFE/ASK/BLOCK 是动作风险，本接口没有动作风险计算或审批调用。**

来源摘要只存经脱敏的 summary/description，合计 JSON 不超过 2048 UTF-8 字节。去掉任意 labels、annotations 附加字段、generatorURL、externalURL 和原始 payload；文本中的常见密码/令牌字段、Bearer/Basic、常见密钥前缀、URL 和邮箱被替换。外部 ID 触发脱敏时改用 sha256 稳定哈希，避免不同来源 ID 被同一占位符折叠；级别/type raw 同样脱敏。自由文本脱敏是规则处理，接入方仍应只发送不含凭据/个人资料的运维摘要；不能声称规则能识别任意隐私形式。

新 Incident ID 为 `LIVE-<UUIDv4>`。详情的 `incident` 仅含 `incident_id/service/alert/started_at`，扩展信息在 `metadata/alerts`，不会破坏 Python `extra=forbid` 模型。严格 `INC-xxx` Fixture 工具、案例格式和测试均保持原样。来源摘要是外部数据，本步不进入 Agent Prompt、工具返回或检索库。

## 投递、告警 occurrence 和 Incident 聚合

三种身份独立：

1. 投递键：凭据所属账户＋source 命名空间＋入口类型＋显式 `Idempotency-Key`（1—128 字母数字或 `._:-`）；未指定则用归一化、脱敏后批内容的 SHA-256。批顺序不影响内容键，接收时间与传输 groupKey/receiver/URL 不影响它。同一显式键同一内容返回原回执，内容改变则 409；不同账户/来源各有命名空间。
2. occurrence 键：账户/source＋服务＋环境＋指纹＋starts_at＋external_id。新投递键不会重复建同一 occurrence；同一 occurrence 的恢复状态更新原行。精确的旧 firing 内容若是原投递重试，返回原历史回执；新投递的过期 firing 不重开已恢复 occurrence，`applied=false`。
3. 聚合键：账户/source＋服务＋环境＋指纹＋episode。首次 firing 的开始时间锚定 15 分钟半开窗口 `[started_at, window_end)`，不被后续告警延长；等于右边界即新 episode，早于锚点的告警不回写旧窗口。来源/账户、服务、环境、指纹不同则分开。

优先提供稳定 fingerprint；未提供时根据 source/服务/环境/type/脱敏 summary 生成，动态 summary 可能产生新指纹。external_id 缺省为空；需区分同指纹同开始时刻的不同告警时，来源必须提供不同 external_id。

全部 occurrence 恢复后关闭聚合窗口；同一指纹的新 starts_at 开新 episode。超过接收时刻 1 小时的迟到告警隔离并标 `late=1`；未见对应 firing 的恢复通知隔离为 `orphan_resolution=1`。窗口、迟到政策为本版本固定规则，不承诺监控事件任意乱序仍自动合并。

批次预先验证全部 scope；存储使用 `BEGIN IMMEDIATE` 事务、唯一投递键/occurrence 键/聚合键及 `(aggregation_base,episode)` 约束。失败整批回滚；并发竞争等待 SQLite busy_timeout，成功才返回回执。不用“先查后写”的进程内锁冒充跨进程一致性。

**resolved 告警只更新告警与聚合窗口。Incident 调查状态固定为 RECEIVED，不会自动 RESOLVED。** 本步的投递回执是接入记录，不是 AgentEvent 调查时间线；第 5 步从持久化事件建立合法 Lifecycle 和调查任务，不能把本步查询称为完整调查完成。

## Alertmanager 协议范围

兼容 v4 JSON Webhook 的 `version/receiver/status/groupKey/groupLabels/commonLabels/commonAnnotations/alerts/externalURL/truncatedAlerts` 和每条 alert 的 `status/labels/annotations/startsAt/endsAt/fingerprint/generatorURL`。使用每条 alert 的状态；source 固定 `alertmanager`。要求每条 labels 明确提供 `service/environment`；级别取 `severity`，缺省取 `priority`，否则 unknown。external_id 取 labels.external_id 或 fingerprint；摘要取 annotations.summary 或 alertname；描述取 annotations.description。truncatedAlerts 随回执保存并明确显示，不假装接收了被截断告警。

在实际 Alertmanager 中需补齐这两个标签并为 Webhook receiver 配置专用 Authorization。这里只证明协议样本可接收，**尚未连接真实 Alertmanager，也未验证实际监控规则、路由、重试/恢复投递、网络和 TLS**。手工 POST、本地 HTTP 和 in-process API 测试均不等于监控联调通过。

## 数据库与兼容

源码 schema 69 → 70，沿用 `initDatabase` 的迁移前备份门（失败则拒绝迁移）和同一个 SQLite connection；创建五张独立表：`incident_ingest_credentials/incident_live_records/incident_alert_occurrences/incident_alert_deliveries/incident_alert_delivery_items`。delivery_items 为批次与 occurrence 关联表，便于原子批量去重。只新增表和索引，不重写原用户/Session/消息/任务/Agent/Fixture 数据。版本标记在建表成功后更新。

本步没有读取或迁移用户实际运行 DB；迁移/重启验收只用了本任务独立测试 DB。正式宿主下次初始化将按既有备份门执行增量迁移。SQLite 的既有 WAL＋NORMAL 策略保留：正常关闭重开已验证，断电耐久性不在本步实测范围。

## Windows PowerShell 示例

以下对**用户已有且有权访问的本地 Web 服务**发手工 POST，不启动服务，不写 token 文件。第 2 步自动验收使用下节隔离脚本，不能在真实生产服务上演练。把 `$api` 改为授权的本地地址；密码由 Get-Credential 输入，只在请求时暂存内存；不输出凭据响应，不保存命令 transcript。

```powershell
$api = 'http://127.0.0.1:3000'
$loginCredential = Get-Credential -Message '现有管理员账号（仅本地演示）'
$loginBody = @{
  username = $loginCredential.UserName
  password = $loginCredential.GetNetworkCredential().Password
} | ConvertTo-Json -Compress
$null = Invoke-RestMethod -Method Post -Uri "$api/api/auth/login" -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($loginBody)) -SessionVariable adminSession
$me = Invoke-RestMethod -Uri "$api/api/auth/me" -WebSession $adminSession
$credentialBody = @{
  owner_user_id = $me.user.id
  source = 'demo'
  scopes = @(@{service='orders'; environment='local'})
  expires_at = (Get-Date).ToUniversalTime().AddHours(1).ToString('o')
} | ConvertTo-Json -Depth 5
$issued = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/credentials" -WebSession $adminSession -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($credentialBody))
$headers = @{ Authorization = "Bearer $($issued.token)"; 'Idempotency-Key' = 'local-pool-delivery-1' }
$started = (Get-Date).ToUniversalTime().AddSeconds(-10).ToString('o')
$alert = @{
  source='demo'; external_id='pool-local-1'; service='orders'; environment='local'
  severity='critical'; alert_type='PROBLEM'; fingerprint='connection-pool'
  starts_at=$started; status='firing'; summary='本地连接池耗尽'
} | ConvertTo-Json
$bodyBytes = [Text.Encoding]::UTF8.GetBytes($alert)
$first = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/webhook" -Headers $headers -ContentType 'application/json' -Body $bodyBytes
$retry = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/webhook" -Headers $headers -ContentType 'application/json' -Body $bodyBytes
$first.delivery_id -eq $retry.delivery_id   # True
$retry.duplicate                            # True
$detail = Invoke-RestMethod -Uri "$api/api/incident-alerts/incidents/$($first.items[0].incident_id)" -Headers @{Authorization="Bearer $($issued.token)"}
$detail.metadata | Select-Object status, alert_status, severity, unknown_severity_count, alert_count, delivery_count
# 本步：status=RECEIVED；alert_status=firing。不能视为调查解决。
$null = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/credentials/$($issued.id)/revoke" -WebSession $adminSession -ContentType 'application/json' -Body '{}'
Remove-Variable issued, headers, loginBody, loginCredential, credentialBody
# 如不继续运行下面 AM 样例，可在此 Remove-Variable adminSession。
```

Alertmanager 人工协议样本（先使用上述管理员 Session 签发 source=`alertmanager` 的独立凭据，勿复用 source=`demo` 的令牌）：

```powershell
$amCredentialBody = @{
  owner_user_id=$me.user.id; source='alertmanager'
  scopes=@(@{service='orders'; environment='local'})
  expires_at=(Get-Date).ToUniversalTime().AddHours(1).ToString('o')
} | ConvertTo-Json -Depth 5
# 使用上例仍有效的管理员 Session；本段单独运行时应先登录。
$amIssued = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/credentials" -WebSession $adminSession -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($amCredentialBody))
$am = @{
  version='4'; receiver='local-incident'; status='firing'; groupKey='local-pool'
  groupLabels=@{}; commonLabels=@{}; commonAnnotations=@{}; truncatedAlerts=0
  alerts=@(@{
    status='firing'; labels=@{alertname='PoolExhausted';service='orders';environment='local';severity='critical'}
    annotations=@{summary='本地连接池耗尽'}; startsAt=(Get-Date).ToUniversalTime().ToString('o')
    endsAt='0001-01-01T00:00:00Z'; fingerprint='local-am-pool'
  })
} | ConvertTo-Json -Depth 6
$amReceipt = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/alertmanager" -Headers @{Authorization="Bearer $($amIssued.token)"} -ContentType 'application/json' -Body ([Text.Encoding]::UTF8.GetBytes($am))
$amReceipt.items | Select-Object incident_id, occurrence_id, applied
$null = Invoke-RestMethod -Method Post -Uri "$api/api/incident-alerts/credentials/$($amIssued.id)/revoke" -WebSession $adminSession -ContentType 'application/json' -Body '{}'
Remove-Variable amIssued, amCredentialBody, adminSession
```
