# v0.3.0 第 6 步：Console 现场调查

> 阶段历史说明：本文保留该步实施时的职责与命令；后续已串联为 v0.3.0 当前链路，最新状态及失败项以[第 8 步审查](v0.3.0-review.md)为准。

本步复用现有前端、Hono、Cookie Session、SQLite schema 71。没有常驻 Worker、推送、生产数据源或现场执行器；不会因打开页面自动调查。浏览器验收使用独立测试数据库、本任务启动的 loopback 服务及实际运行中的日志/指标。

## 页面与兼容入口

| 入口                                                      | 内容                                                                     |
| --------------------------------------------------------- | ------------------------------------------------------------------------ |
| `/incidents`                                              | 原模拟 Fixture 列表/筛选/历史状态；增加现场入口链接                      |
| `/investigations`                                         | 实际接入告警、来源/服务/环境/级别、聚合与投递、任务状态                  |
| `/investigations?id=LIVE-…`                               | 元数据、首次/最近发生与接入、故障窗口、任务轮次/租约/重试/错误与后续动作 |
| 同页 `tab=report/evidence/knowledge/attempts`             | 已保存报告、观测与手册独立分区、实际 Pi 工具尝试                         |
| `/traces?mode=live&id=LIVE-…&run=RUN-…&tab=events/replay` | 实际事件、只读历史回放                                                   |
| `/traces`、`/approvals`                                   | 原 JSONL 历史及可信宿主模拟审批；原 Gate 不变                            |

任务排队、执行、重试、最终失败、完成、需人工处理、待补齐来源/模型分别显示。未取得报告不填根因；事实引用显示 Evidence items 索引/字段；假设、手册建议与验证字段分开。手册保留章节、版本/内容哈希、原片段、行号及字符位置，不成为当前故障成立的 Evidence。影响范围只确认服务/环境，未观测的用户或依赖范围明确不足。模型 confidence 不授予执行权。

来源标识基于已落库观测和宿主绑定：原页“模拟 Fixture”；存在现场 Evidence 为“本地受控服务实时观测”；已绑定但没有有效观测显示该边界；无绑定显示“未接入数据源 · 尚未绑定”。成功空结果、截断/保留不足和查询错误分别在观测/追踪显示。告警恢复不等于调查 RESOLVED。

## 只读 API 与服务端限制

路由属于现有 `/api/incident-alerts`，要求有效 Cookie Session 和 `ingest_alerts`，或现有有效专用告警 Bearer。普通成员只读自身有效来源 grant 下的服务/环境；管理员沿用当前全范围规则。无登录 401、无权限 403、跨范围与跨 Incident/run/reference 404。Bearer 无管理或审批权限，不新增匿名入口。

| 方法/路径                              | 参数/返回                                                                                                                                |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /console/incidents`               | `service/environment/source` 可选；`limit` 1–20，默认 10；`offset` 0–10000。返回实际聚合记录、最新任务/运行摘要、has_more                |
| `GET /console/incidents/:id`           | 实际元数据、最多 20 代任务与每代尝试，分页告警投递/聚合明细；limit/offset 同上                                                           |
| `GET /console/incidents/:id/runs/:run` | `section=report/evidence/knowledge/events/replay/attempts`，默认 report；limit/offset 同上；evidence/knowledge 可用 `reference` 精确定位 |

生产挂载为 `/api/incident-alerts/console/…`，上表路径是该路由族的相对路径。前端观测默认每页 2，其他默认 10。列表服务/环境过滤不能扩展宿主授权。LIVE ID 与 RUN ID 严格校验；不接受 URL、路径、凭据、任意文件或工具执行参数。

输出先取受限任务字段，再递归脱敏自由文本、凭据字段、源地址、账户/租约内部字段、个人路径、邮箱与令牌；手册和聚合的内容哈希保留。每个响应最多 256 KiB、字符串 64 Ki 单元、结构深度 12、数组最多 500；超限 413，不返回截断的假报告。大事件工具正文超过 8 KiB 时仅投影原真实事件元数据并标 `payload_truncated`，UI 明确提示完整内容所在分区。原事件数据库不改写。共享邮箱脱敏加长度边界，防止长响应匹配阻塞。

第 5 步原调查 GET 也执行脱敏和总大小限制，新 UI 使用上述分页接口。所有现场 API `Cache-Control: no-store`。前端只显示不能授予权限；原审批仍必须由可信宿主 Gate 校验具体动作/目标/参数/Incident/有效期。

回放只 GET 已保存事件，最多缓存 140 项，保留真实 ID、顺序和状态；播放、暂停、下一事件、重置仅修改视图。大 payload 的展示省略不改事件与状态。运行尚无真实生命周期事件时展示空状态，不重新采集或制造事件。

## Windows PowerShell 验收

在实际 Git 仓库执行：

```powershell
npm run typecheck
npm --prefix container/agent-runner run build
npm run build:web
npx tsx scripts/accept-v030-step6.ts --legacy-ui
```

需已有 Playwright Chromium。本任务没有安装浏览器或依赖；若当前默认版本不可用，可在本地会话设置 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指向已安装的 Chromium，再运行同一命令。路径和凭据不写报告。仅首次需要选择有效现有浏览器，不代表允许下载新的基础设施。

脚本流程：

1. 创建私有临时根、独立 full schema 测试 DB、测试账户/随机内存签名会话，使用原 authMiddleware；仅测试壳跳过 Provider 引导，不读取个人配置或调用模型。
2. 使用实际业务路由；复制原 12 Fixture，不复制 evaluation 标准答案、case matrix、Runbook 评测或历史用户日志。原 Python 生命周期产生一份明确模拟的 INC-001 RECEIVED→INVESTIGATING→ESCALATED 历史，没有假诊断。
3. 启动自有连接池资源槽服务，通过实际并发请求产生超时，再 POST 接入并运行第 5 步只读 Worker。真正采集指标/日志、检索手册、落库实际事件与事实字段；无模型时 blocked/ESCALATED，不生成根因。
4. 用真实原领取/重试方法建立排队、执行中、等待重试、最终失败场景。Chromium 1440×900 访问生产前端构建，经真实 API 验证列表→详情→事实观测引用→手册引用→追踪→回放，并覆盖空数据、无权限、未登录、旧 Fixture/历史/审批壳。
5. 验证回放无写请求、该 run 全历史读前读后相同；截图只含测试数据。`--legacy-ui` 再运行原 Console 两项 API 拦截 UI 回归，目录与历史同样隔离；不把拦截回归算成后台联调。
6. 关闭本次浏览器、服务和数据库，删除自己的临时文件；不关闭未知服务。只保留仓库外 `../output/v0.3.0-step6` 的截图/非敏感验收摘要，可用 `INCIDENT_CONSOLE_QA_OUTPUT` 指定仓库外目录。临时服务端口随机；脚本退出后不留可登录演示系统。

已有登录会话的分页查询示例（不打印 Session/凭据）：

```powershell
# $session 为现有合法登录 WebSession；以下不会创建任务或调用模型。
$base = 'http://127.0.0.1:3000/api/incident-alerts/console/incidents'
Invoke-RestMethod "$base`?service=orders&environment=local&limit=10&offset=0" -WebSession $session
# 从返回结果选择真实 ID，不手写 Fixture ID 冒充现场来源。
```

默认场景不配置模型，模型 HTTP 数为 0。第 5 步真实 Provider 最终诊断仍未验收通过。本地人工 POST 证明入口兼容，不等于实际 Alertmanager 监控联调；资源槽服务也不是生产数据库。当前页面通过刷新读取持久化结果，无推送或持续后台调查。生产、真实处置、外部通知、第 7 步恢复综合验收及发布均未在本步执行。
