# 第 5 步：持久化调查任务与受限执行

> 阶段历史说明：本文保留该步实施时的职责与命令；后续已串联为 v0.3.0 当前链路，最新状态及失败项以[第 8 步审查](v0.3.0-review.md)为准。

本步适用于本任务的本地受控资源槽演示；不是生产数据库、真实 Alertmanager 联调或自动处置。模型结果、协议桩和宿主升级结论分别标记 `real_pi`、`protocol_stub`、`host_no_model` / `host_control`。通知只保存本地记录。

## 调用链与兼容方式

认证 Webhook / Alertmanager → 原归一化/聚合事务 → SQLite 调查任务 → 原子领取与租约 → 宿主 Python 生命周期薄适配 → 隔离 Runner → 原 SAFE 工具与真实只读 Provider / Runbook → 有界 Pi 会话 → 引用校验 → 原生命周期诊断/升级 → fenced 结果事务 → 查询 / 历史导出 → 原只读 Replay。

使用现有 SQLite，schema 70→71 新增八表：jobs、runs、events、evidence、runbook_chunks、knowledge、approvals、model_requests，复用旧迁移备份机制。无新依赖或 Redis。聚合入口记录仍保留原 `RECEIVED` 语义；调查状态单独由每个 run 的原生命周期记录，查询同时给出任务状态与 run 状态。恢复告警不使调查自动 `RESOLVED`。

`Incident` 仍四字段、`Evidence` 仍六字段；环境、来源、观测/查询时间、run/query ID 放在宿主 binding 和 Evidence.content。严格 INC-xxx Fixture 路径、原模拟工作流、审批控制与 Replay 未放宽。知识引用保存在独立表、不可变 chunk 与 ToolResult 快照，不生成 EvidenceCollected。

宿主是 SQLite 写入者。新 Runner 是独立编译入口，使用原 Pi Adapter/Session/Provider 和 MCP→Pi 适配，受限 NDJSON 请求由宿主验证、写入并确认。没有跨 rootDir 静态导入或改造通用 Runtime。模型 cwd/session/agentDir 均在本任务临时空目录；只注册四个现场取证工具和 search_runbooks。未注册读文件、Bash、写入、通用 Agent、审批或处置工具；工具返回不含宿主凭据/来源地址。只显式读取五份 Runbook，不检索 evaluation、标准答案或设计文档。

## 聚合、幂等与恢复规则

- 投递键继续由第 2 步处理；调查幂等键是 Incident + generation 的 SHA-256。数据库唯一键和单 Incident 活动任务的部分唯一索引兜底，领取用 `BEGIN IMMEDIATE` 事务与条件更新。
- 初次 firing 生成 queued；resolved-only 不新建任务。首次领取前告警合并进 snapshot/revision；领取后及 retry_wait 冻结本轮输入，只提高 pending_revision。完成后新告警仍记 pending，不自动重启终态或反复调用模型。需要重新调查时，由有权限的管理员会话明确建立下一 generation；活动中返回 409。
- 新环境、指纹或故障时间窗口产生独立 Incident，按原聚合规则建立独立任务。迁移前告警由宿主 `scanPending()` 分批补队列；仅扫描尚无任务的记录。
- 每个 run 独立 UUID。租约默认 30 秒、10 秒心跳；每次预算、事件、证据、知识、结果与审批写入均检查 owner/token/run/到期时间。过期回收进入 retry_wait，10 秒后至多再尝试一次，总计最多两次；第二次失败进入 failed。墙钟到期直接 manual，不重试。
- 重启的新宿主重新打开同一数据库并调用 claim/reap 即可恢复；旧 Worker 无法续租、记账或提交新租约的结果。历史 attempt 保留，不覆盖旧 Evidence。没有新增常驻系统服务，主应用接入事务只入队；执行需显式启动宿主 Worker。

## 预算、报告和审批

单 run 最大墙钟 180 秒（CLI/演示 60 秒），工具尝试预留 8 次、Runbook 2 次、模型 HTTP 6 次；同 generation 两次尝试总工具 16、检索 4、模型 HTTP 12。CLI/验收模型上限更窄为 3。预留不因失败或重启退还。

模型走宿主固定目标的 loopback 预算代理，真实上游仅现有配置的 HTTPS Provider，不让 Agent 输入 URL/凭据。每个实际 HTTP 请求先持久化预留，30 秒请求超时、256 KiB 输入、1 MiB 输出、4096 输出 token 上限，重定向拒绝；SDK 重试也必须经过同一预算。取消只终止本任务拥有的进程、连接和服务。墙钟到期后拒绝任何结果写入，进程清理有短暂宽限；Python 宿主子进程另有 10 秒上限。

原 ToolCalled/ToolResult/EvidenceCollected/ToolFailed 保存实际工具执行；额外 `runtime_tool_attempts` 只保存 Pi 实际发出的 start/end 投影，含参数校验失败、预算拒绝等尝试。它不是执行成功证明。相同 call ID 的流式/执行通知共用一次预算预留；参数只保存受限字段和脱敏文本。未知工具仍 BLOCK，不获得权限。

报告区分 `facts`（观测 item 的受限字段和值）、`hypotheses`、`handbook_suggestions`、`conflicts`、`limitations` 和 `next_evidence_requests`。宿主校验证据/知识 ID 存在、Incident/run 归属、服务/环境、查询时间、类型和字段值相等，落库及历史读取再次校验。根因文字仍是模型诊断主张，`semantic_proof=false`；这些结构检查不是通用语义证明，也不能从样本推出生产因果关系。冲突列表来自显式报告，不宣称实现了通用冲突识别器。

模型显式冲突、任一失败取证、无模型、结构不合法、重要数据源不可用或预算耗尽，收敛到升级原因/补证据需求。成功空查询有 Evidence；查询失败没有伪造 Evidence。Trace/Git 仍明确 unsupported，无 Fixture fallback。默认查询是领取时附近的本次观测窗口（最多 15 分钟，实际默认最近 60 秒），不把晚到观测当作历史故障发生时的数据。

本步调查只读。模型 proposal 没有批准或执行能力。独立 `BoundInvestigationApprovals` 供可信宿主持有，绑定 action/target/parameters/Incident/run/租约 token/宿主活句柄/最长 60 秒有效期，参数哈希校验并一次性决定；恢复后无活句柄，旧租约和过期申请拒绝，结束/回收作废 pending。其 approved 是意图记录，仍 `execution_authorized=false`，不调用执行器。原 Fixture 模拟审批链保持；现场执行与 Console 审批展示需后续授权阶段，不得将 confidence 作为授权。

Set-Location 'D:\agent应用开发求职\线上服务故障排查与处置agent\miniclaw-main'
npm --prefix container/agent-runner run build
node node_modules/tsx/dist/cli.mjs scripts/accept-v030-step5.ts

如需对已创建的独立本地演示 DB 执行一批任务，宿主 CLI 支持：

```powershell
# 两个变量指向本任务已有的独立 DB 和私有来源 JSON，不使用个人运行 DB
node node_modules/tsx/dist/cli.mjs scripts/incident-investigation-worker.ts --db $demoDatabase --source-config $privateSourceJson --ticks 1
```

来源 JSON 是宿主私有 `HostIncidentSource[]`：source_scope（原 owner/source 摘要）、source_id、service、environment=local、base_url（字面 127.0.0.1）、read_token、instance_id。Agent 不能创建/修改该配置；不要把文件、凭据、DB 或运行日志放入 Git/报告。CLI 不初始化或迁移个人 DB，拒绝项目 data/ 下的运行 DB、链接、超大配置和非本地来源；ticks 1–10 有限，遇到 idle 停止。验收脚本的 `--worker-process` 已在临时私有来源文件上实际执行这条 CLI。

## 查询与只读历史

复用第 2 步身份与 ingest_alerts 权限，来源/服务/环境范围先检查：

- GET `/api/incident-alerts/incidents/:id/investigations`：任务、租约状态/尝试、pending_revision、每个 run 摘要与本地通知。
- GET `/api/incident-alerts/incidents/:id/investigations/:run`：观测 Evidence、独立 KnowledgeReference、实际工具事件/尝试、最终报告和预算计数。
- POST `/api/incident-alerts/incidents/:id/investigations`：仅管理员签名会话显式重查；机器 Bearer 与普通成员拒绝，活动任务冲突。它只建立任务，不批准动作。

```powershell
# 接入 token 只查询其授予的范围，不能调用重查管理接口
$headers = @{ Authorization = "Bearer $env:FAULT_DEMO_INGEST_TOKEN" }
Invoke-RestMethod -Method Get -Uri "$base/api/incident-alerts/incidents/$incidentId/investigations" -Headers $headers
Invoke-RestMethod -Method Get -Uri "$base/api/incident-alerts/incidents/$incidentId/investigations/$runId" -Headers $headers
```

`investigationHistory` 无 Provider/Runbook/model 导入，读取已保存引用/内容和事件。`exportInvestigationReplay` 只向宿主指定的新私有目录原子导出单个 run 的 JSONL，拒绝覆盖；原 Python Replay 重新验证十种事件/合法状态/工具与证据关联，绝不重新检索、取证、调用模型或批准动作。数据库是历史权威源，不以 JSONL 是否导出作为任务完成条件。

如果进程在领取后、首个生命周期事件写入前崩溃，任务仍有领取/失败记录，run 可能无事件；历史 API 如实返回空 timeline，JSONL 导出明确拒绝 `history_has_no_events`，不得补造工具或生命周期轨迹。
