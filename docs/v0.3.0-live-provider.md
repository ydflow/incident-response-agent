# v0.3.0 第 3 步：本地实时只读取证

> 阶段历史说明：本文保留该步实施时的职责与命令；后续已串联为 v0.3.0 当前链路，最新状态及失败项以[第 8 步审查](v0.3.0-review.md)为准。

本步数据来自**运行中的、本任务创建的 Node HTTP 资源槽演示服务**。它沿用连接池容量不足、排队等待、获取超时这一场景，实际执行 HTTP 请求与有限资源槽的获取/持有/释放；没有连接生产数据库，也不是读取静态 JSON 冒充实时响应。模型、Runbook、持久化调查任务、现场 Console 页面和自动告警规则仍属于后续步骤。

## 兼容与调用链

```text
可信宿主：固定来源配置＋LIVE Incident 绑定＋本次 run ID＋Gate
  → createMcpTools({incidentProviderRoute, incidentApprovalGate, ...})
  → createIncidentProviderTools（只返回四个只读工具）
  → withIncidentToolEvents（原包装、5 秒截止）
  → Gate.runSafe（四个 query_live_* 明确 SAFE，未知工具仍 BLOCK）
  → LocalDemoProvider（校验 ID/scope/时间窗/预算）
  → 固定 /observations/logs 或 /observations/metrics
  → 实际服务内有界缓冲与当前观测
  → 六字段 Evidence → 原 collector＋ToolResult/EvidenceCollected
```

Pi 工具名为 `mcp__incident_live__query_live_logs/metrics/trace/git_diff`（分别以完整 query_live 名称注册）。没有 shell、任意 HTTP、读文件、配置变更、源注册、模型调用或审批决定工具。`createMcpTools` 只新增显式宿主注入的早期选择分支，并要求显式 Gate；未注入时走原 MiniClaw 通用/Fixture/审批路径，原职责不变。

`FixtureProvider` 只是 `createIncidentEvidenceTools` 的薄包装；原 loader、严格 INC-xxx ID/路径/五文件校验、六字段结果和空 Trace 语义完全保留。现场没有 Fixture fallback，LIVE ID 从宿主 Map 查绑定，绝不作为文件路径。Runtime、模型 Provider、Session、Pi Adapter、原事件包装/collector、审批执行、Replay 未重写；归属仍见 [project-ownership](project-ownership.md)、LICENSE、NOTICE。

## 宿主配置与取证边界

`LocalDemoProvider(sources, bindings, runId)` 是可信宿主 API，不是 Agent Tool：

- sources 固定 `source_id/base_url/service/environment/read_token`，可绑定服务 `instance_id`。本阶段只接受显式 `http://127.0.0.1:<合法端口>`，无 DNS、用户名密码、query、路径或 redirect；最多 16 个来源。HTTP Authorization 不进入工具 Schema、Evidence、事件或报告。
- bindings 固定 `incident_id/source_id/service/environment/allowed_from/allowed_to`；ID 必须 LIVE-UUIDv4，最多 32 项，允许范围最多 15 分钟。实际告警绑定应从第 2 步存储里已授权的 Incident/metadata 构建；Agent 不能注册来源或自建绑定。
- Agent 可提交绑定 ID、可选 source/service/environment（只能与绑定一致）、from/to 与 limit。无 URL、路径、token 参数；schema 外参数直接调用 Provider 时拒绝。原 Pi prepareArguments 会过滤 schema 外参数，它们不会成为网络或文件目标。
- 默认查询最近 60 秒与绑定范围的交集；显式窗口必须完全包含于宿主范围，非空、不读未来、最长 15 分钟。所有参数在请求前校验。
- 单查询最多 200 条；服务最多保存各 2000 条日志/指标，包含累计 `retention_dropped`。返回最新符合条件的有界子集，仍按时间升序；条数/字节截断显示 truncated，不声称覆盖全部历史。
- 服务响应与完整 Evidence 各最多 64 KiB（演示服务先限 payload 48 KiB）；宿主 run 的累计读取/返回计费上限 256 KiB、最多 16 个受理查询。并行先保守预留每查询 64 KiB，余量不足时拒绝；大失败响应也计费。本步的局部工具预算不替代第 5 步的模型/Worker 请求预算。
- Provider 默认请求截止 4 秒，宿主可缩短到 10 ms，最高 4.5 秒，早于原工具包装 5 秒；AbortSignal 贯穿 fetch/响应读取，终止后不能晚到追加 Evidence。
- 校验来源/实例/服务/环境、query_id、实际观测时间、精确窗口、条数、数据结构与时间升序/范围；拒绝额外字段、错配或过时响应。失败不返回来源原始 body 或异常内容。

## Evidence 与错误

每次成功查询的 `evidence_id=LIVE_ID:run_id:source:query_uuid`，query_uuid 由宿主生成，重复采集不会覆盖旧 Evidence。顶层仍是原六字段 `evidence_id/incident_id/source/timestamp/content/correlation_id`；content 是有界 JSON：`provider=local_demo/source_id/instance_id/service/environment/query_id/run_id/window/observed_at/status/items/truncated/retention_dropped`。correlation_id 等于 query_id；日志 items 另有实际 request_id，指标有样本观测时间。

| 结果                                                                   | 是否 Evidence | 含义与事件                                                               |
| ---------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------ |
| success                                                                | 是            | 数据来自实际运行服务；ToolCalled → ToolResult → EvidenceCollected        |
| empty                                                                  | 是            | 指定时间窗无保留数据；相同事件序列，content 明确 empty，不等于故障不存在 |
| unsupported                                                            | 否            | Trace/Git 本步未实现；不返回伪造数据，也不回退 Fixture                   |
| unavailable                                                            | 否            | 来源未绑定/停止、认证或网络不可用、HTTP 错误、redirect 被拒绝等          |
| timeout / cancelled                                                    | 否            | 来源截止 / 上游取消；各有不同工具错误码，保留此前 Evidence               |
| invalid_response / response_too_large                                  | 否            | 协议/归属/时间/大小不合法；不使用坏数据                                  |
| scope_denied / time_window_denied / incident_not_bound / invalid_query | 否            | 调用未满足宿主许可或输入边界；不取其他来源                               |
| query_budget_exhausted                                                 | 否            | 本 run 的次数/并发预留/字节额度不足；不继续取数                          |

错误结果沿用原包装产生 ToolCalled → ToolResult(error) → ToolFailed；错误码在工具返回中。原事件包装的 ToolFailed reason 仍是通用错误说明，未把它伪称为包含完整来源异常。取证事件与六字段 Evidence 本步可在原 collector 内保留；验收 JSONL 写到自己的临时目录。SQLite Evidence/任务持久化、初始生命周期与完整 Replay 链在第 5 步，不将本步局部取证事件称为已完成调查或完整回放。

## 演示服务

`src/incident-local-demo.ts` 只监听 127.0.0.1，本任务随机/指定端口；两个不同的 256-bit 临时凭据分别保护只读端点和可信操作者控制端点。Agent 只获得读工具，拿不到控制 token。

| 端点                    | 方法与权限          | 作用                                                                                 |
| ----------------------- | ------------------- | ------------------------------------------------------------------------------------ |
| `/health`               | GET＋read token     | 来源、实例和 scope；不泄露 token                                                     |
| `/work`                 | GET＋read token     | 实际请求争用资源槽；不是 Agent 取证工具                                              |
| `/observations/logs`    | GET＋read token     | 范围内实际获取、超时、完成、取消日志                                                 |
| `/observations/metrics` | GET＋read token     | 实际 capacity/active/waiting、请求/成功/超时/取消/overflow 累计计数、等待总毫秒      |
| `/control/config`       | POST＋control token | 操作者设置 capacity/hold_ms/acquire_timeout_ms/query_delay_ms；从未注册为 Agent Tool |

资源槽 capacity 1—32，队列最多 128，持有 0—2000 ms，获取截止 10—2000 ms；来源查询延迟可控 0—2000 ms。队列取消与超时会移除等待者、持有取消会释放槽位，停止只关闭自己创建的 server 和计时器。指标周期采样与实际请求/配置变化采样并存；原日志只包含固定运维事件码与本服务随机 request_id，不存请求 Header、正文或业务个人数据。

负载最多 100 个请求、并发最多 16、总时限 15 秒、单请求 3 秒。CLI 服务自动在 30—600 秒 TTL 内结束，默认 600 秒。默认健康配置 4/20/500；fault 控制为 capacity=1、hold=500 ms、获取截止 50 ms；recover 为 8/10/500。超时计数是累计值，恢复以**新增负载的成功率和计数增量**验证，不清零历史制造恢复。

## 可复制的 Windows PowerShell 命令

只对本任务的服务执行；不加载个人 Provider 配置，不读取生产 DB。凭据只留在本 PowerShell 及其创建进程的环境中，不写文件/日志/CLI 参数。不要将环境值或凭据响应打印到报告。用已安装的本地 tsx CLI；没有安装依赖。

```powershell
$taskRepo = 'D:\agent应用开发求职\线上服务故障排查与处置agent\miniclaw-main'
Set-Location -LiteralPath $taskRepo
$taskNode = (Get-Command node).Source
$taskLoader = Join-Path $taskRepo 'node_modules\tsx\dist\cli.mjs'
$taskDemoCli = Join-Path $taskRepo 'scripts\incident-local-demo.ts'
$env:FAULT_DEMO_READ_TOKEN = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
$env:FAULT_DEMO_CONTROL_TOKEN = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
$env:FAULT_DEMO_PORT = '43210'
$env:FAULT_DEMO_SOURCE_ID = 'pool-local'
$env:FAULT_DEMO_SERVICE = 'payment-service'
$env:FAULT_DEMO_ENVIRONMENT = 'local'
# 本进程是自己创建的；端口占用时改 FAULT_DEMO_PORT，不结束占用者。
$taskDemoOwned = Start-Process -FilePath $taskNode -ArgumentList @("`"$taskLoader`"", "`"$taskDemoCli`"", 'serve', '--ttl-seconds', '600') -WorkingDirectory $taskRepo -WindowStyle Hidden -PassThru
$taskReady = $false
for ($taskTry = 0; $taskTry -lt 30; $taskTry++) {
  $taskDemoOwned.Refresh()
  if ($taskDemoOwned.HasExited) { throw '本任务服务启动失败；检查输入或选择空闲端口，勿终止其他进程。' }
  try {
    $taskIdentity = Invoke-RestMethod -Uri "http://127.0.0.1:$env:FAULT_DEMO_PORT/health" -Headers @{Authorization="Bearer $env:FAULT_DEMO_READ_TOKEN"} -TimeoutSec 1
    $taskReady = $true
    break
  } catch { Start-Sleep -Milliseconds 100 }
}
if (-not $taskReady) { throw '本任务服务未就绪。' }
$env:FAULT_DEMO_INSTANCE_ID = $taskIdentity.instance_id

# 独立探测绑定 ID；不会自动创建数据库 Incident 或调查任务。
# 已接入第2步告警时，可使用其 LIVE 回执 ID，但服务/环境必须与宿主绑定匹配。
$taskIncidentId = 'LIVE-' + [Guid]::NewGuid().ToString()
& $taskNode $taskLoader $taskDemoCli query --incident-id $taskIncidentId --kind logs
# 初始无实际工作请求：正常 empty Evidence，仍有三个取证事件。

# 有界造故障负载：真实 GET /work，资源槽排队与获取超时。
& $taskNode $taskLoader $taskDemoCli fault
& $taskNode $taskLoader $taskDemoCli load --requests 12 --concurrency 8
& $taskNode $taskLoader $taskDemoCli query --incident-id $taskIncidentId --kind metrics
& $taskNode $taskLoader $taskDemoCli query --incident-id $taskIncidentId --kind logs
# CLI 仅显示 Evidence/provenance/条数/日志事件码或末尾指标，完整数据在工具 Evidence 中。
& $taskNode $taskLoader $taskDemoCli query --incident-id $taskIncidentId --kind trace
# 明确 unsupported，exit 1；没有 Trace Evidence。

# 操作者恢复；不经 Agent 控制，不自动推进 Incident 状态。
& $taskNode $taskLoader $taskDemoCli recover
& $taskNode $taskLoader $taskDemoCli load --requests 12 --concurrency 8
& $taskNode $taskLoader $taskDemoCli query --incident-id $taskIncidentId --kind metrics

# 只停止上述自己创建的原进程；核对实例起始时间，避免 PID 重用。
$taskDemoOwned.Refresh()
if (-not $taskDemoOwned.HasExited) {
  $taskCurrent = Get-Process -Id $taskDemoOwned.Id -ErrorAction Stop
  if ($taskCurrent.StartTime -ne $taskDemoOwned.StartTime) { throw '进程身份不匹配，停止操作已取消。' }
  Stop-Process -Id $taskDemoOwned.Id
  $taskDemoOwned.WaitForExit()
}
& $taskNode $taskLoader $taskDemoCli query --incident-id $taskIncidentId --kind metrics
# 明确 unavailable，exit 1；无新 Evidence。
Remove-Item Env:FAULT_DEMO_READ_TOKEN, Env:FAULT_DEMO_CONTROL_TOKEN, Env:FAULT_DEMO_PORT, Env:FAULT_DEMO_SOURCE_ID, Env:FAULT_DEMO_SERVICE, Env:FAULT_DEMO_ENVIRONMENT, Env:FAULT_DEMO_INSTANCE_ID -ErrorAction SilentlyContinue
```

若需要改自定义配置，操作者可以对自己的端点 POST（不作为 Agent Tool）：

```powershell
# 使用上面尚有效的控制环境；执行结束再清理。
$taskPoolConfig = @{capacity=1;hold_ms=500;acquire_timeout_ms=50;query_delay_ms=150} | ConvertTo-Json
$null = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:$env:FAULT_DEMO_PORT/control/config" -Headers @{Authorization="Bearer $env:FAULT_DEMO_CONTROL_TOKEN"} -ContentType 'application/json' -Body $taskPoolConfig -TimeoutSec 3
# query_delay_ms 可供宿主短截止 Provider 验证 timeout；Agent 不能设置截止或控制配置。
```
