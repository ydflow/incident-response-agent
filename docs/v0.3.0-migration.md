# v0.3.0 迁移、复现与资源管理

本说明对应发布候选工作树；不表示已部署、迁移个人数据库或发布。版本来源是 [product-version.ts](../web/src/features/incident-console/product-version.ts)，与根包/Runner/Electron 1.0.0、Web 0.0.1 分开。

## 数据与历史兼容

- 复用原 SQLite 连接。schema 69→70 添加五张告警表；70→71 添加八张调查/引用/预算/审批表及索引。原表定义/数据不删除，迁移前沿用宿主数据库备份机制，备份失败拒绝升级；新于 71 的库拒绝降级。
- 原 Incident/Evidence/Diagnosis 的 extra=forbid 不变。告警来源/环境/投递/聚合元数据存侧表和任务快照；现场来源/观测范围存 Evidence.content。严格 INC-xxx 的 Fixture Loader 不变，现场 LIVE UUID 不作为文件路径。
- 任务按故障窗口建立一条活动记录；排队前新告警合并，运行期间冻结输入并增加 pending_revision，终态后不自动新开模型调查；管理员显式重查建立新 generation。
- schema 71 任务快照新增可选 task_kind=recovery_verification，无新增迁移、旧快照仍有效。只读恢复验证异常/租约过期转 manual，普通 Worker 不重试它；宿主明确重试验证需新一轮任务，不会重新执行人工恢复配置。
- 原十种 AgentEvent/JSONL/Replay 保留；恢复记录存报告侧信息，回放仅读取历史。并发 JSONL 导出使用排他发布，已有目标不覆盖。
- 旧审批与模拟执行保留；现场绑定批准也没有执行权，重启/失租不恢复批准。resolved 告警只关闭告警聚合窗口，不绕过状态机设置 RESOLVED。

仅独立测试库验证迁移，未操作个人运行库。部署者未来升级自己的数据前，应停止自己管理的实例并保留完整备份（包含一致性处理后的 WAL），验证备份可读；回滚应恢复升级前一致性备份，不能把 schema 71 库交给 schema 69 程序并强行改版本号。本步骤不执行这些部署操作。

## 依赖与启动

延用已配置 Node/Python/React/SQLite/auth，无新数据库、Agent 框架、向量库或包依赖。建议 Node 24、Python 3.13；宿主优先使用仓库 .venv 的解释器，否则 Windows 使用 py -3.13、POSIX 使用 python3。Linux CI 显式配置 Python 并在测试前构建独立 Runner。

```powershell
# 在实际 Git 仓库根目录；首次安装由操作者执行，当前步骤没有重新安装依赖
npm ci
npm --prefix web ci
npm --prefix container/agent-runner ci
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r incident_agent/requirements.txt
npm run build:all
node node_modules/tsx/dist/cli.mjs scripts/accept-v030-step7.ts --legacy-ui
```

验收命令自己创建随机端口的资源槽服务和 Hono API、独立测试 DB、临时账户与私有工作目录，实际生成请求/阈值告警，并启动已有 Chromium。最后关闭自己的浏览器/子进程/HTTP 服务/DB、移除私有临时目录。截图及非敏感 acceptance.json 留在仓库外 output；不可把整个 output/data 目录加入 Git。

可选 `--configured-model` 只读取得已有启用 Provider，一轮最多两次 HTTP 预留、有限墙钟；不可用/超时/不合格输出如实升级，不能拿确定性协议桩当真实诊断。不要复制个人 Provider 文件。

## 单独演示与清理

分开的启动、造故障、查询、恢复与停止 PowerShell 命令在[本地 Provider 说明](v0.3.0-live-provider.md)。启动必须保留自己创建的 Process 对象和起始时间；停止前复核 PID/起始时间，只停止该进程。CLI 默认有限 TTL 自行结束；读 token 与 control token 分开，Agent 不持有控制能力。

不可使用按端口批量 kill、仓库 make stop 或结束未知进程来腾端口。若端口已占用，改用自己另选的端口；完整验收使用随机端口。删除任务目录应只使用本次创建并持有的绝对路径。例如：

```powershell
# ownedDemoDir 只能来自本任务此前创建并保存的专用目录对象
$taskCleanupRoot = [IO.Path]::GetFullPath($ownedDemoDir)
$taskTempRoot = [IO.Path]::GetFullPath([IO.Path]::GetTempPath())
if (-not $taskCleanupRoot.StartsWith($taskTempRoot, [StringComparison]::OrdinalIgnoreCase) -or
    [IO.Path]::GetFileName($taskCleanupRoot) -notmatch '^v030-(step[2-8]|investigation)-' -or
    -not (Test-Path -LiteralPath $taskCleanupRoot -PathType Container)) { throw '拒绝清理非本任务目录' }
# 先确认自己的服务/DB 已关闭；不遍历或删除其他目录
Remove-Item -LiteralPath $taskCleanupRoot -Recurse -Force
```

前缀检查不替代所有权：ownedDemoDir 不应通过扫描临时目录猜测。本轮只清理持有的私有验收目录和隔离 HEAD checkout；其中 node_modules junction 先单独移除，不递归进入原依赖目录。未停止未知服务。迁移说明不授予生产操作权限。
