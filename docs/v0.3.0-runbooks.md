# v0.3.0 第 4 步：Markdown / BM25 Runbook 检索

> 阶段历史说明：本文保留该步实施时的职责与命令；后续已串联为 v0.3.0 当前链路，最新状态及失败项以[第 8 步审查](v0.3.0-review.md)为准。

本步实现小规模、确定性词法检索。五份项目独立编写的通用手册只提供调查步骤、处置前提、风险与恢复指标；不按案例 ID 写答案，不证明当前根因。没有向量库、Embedding、外部重排模型或生产 RAG 验证。

## 来源和调用链

可信宿主加载 [`runbooks/manifest.json`](../runbooks/manifest.json) 的显式清单与其中五个 Markdown。只接受名为 runbooks 的独立目录、单层小写 Markdown 文件名；拒绝越界、符号链接、非 UTF-8、受保护答案标记和按案例 ID 映射的内容。不会遍历仓库、docs、evaluation、Fixture、个人 Memory 或 Agent 工作目录。manifest 是手册的范围元数据；Agent 没有读文件、修改清单或重建索引工具。

当前白名单适用 local/staging；服务清单按手册分别列为 payment-service、orders、api-service、worker-service、db-service 的子集。这里是样例适用范围，不能当作已经连接这些环境的系统。

```text
host manifest -> immutable Markdown/BM25 index
host Incident/service/environment/doc grants -> IncidentRunbookSearch
isolated McpContext -> search_runbooks -> original SAFE Gate
                    -> ToolCalled / ToolResult + frozen knowledge_result
                    -> separate KnowledgeReference / investigation context
history ToolResult -> readRecordedKnowledge (no file/index/search/model)
```

[`incident-runbooks.ts`](../container/agent-runner/src/incident-runbooks.ts) 负责加载、切片、过滤和 BM25；[`incident-knowledge.ts`](../container/agent-runner/src/incident-knowledge.ts) 负责 strict DTO、工具、知识收集与历史投影。原 MCP 工厂仅在已由宿主选择的隔离 Incident route 上附加检索工具。未注入知识时仍是原来的四个取证工具；普通 MiniClaw 会话不会自动获得检索或文件权限。

复用原 Gate 新增一项明确 SAFE，未知文件/写入工具仍 BLOCK，处置仍 ASK。原事件包装只增加可选的宿主结果快照回调；事件类型和核心字段不变，快照不能覆盖 tool/tool_call_id/status。`collectsEvidence=false`，检索不产生 EvidenceCollected。

## 切片、版本与排名

按 ATX Markdown 标题层级与空行段落切分；标题也作为独立块，代码围栏内的标题不改变章节。长段最多 1000 UTF-16 单元，相邻块最多 120 单元重叠，避免切断代理对。保留原片段、UTF-16 起止位置（end exclusive）、1-based 行号、标题、章节路径、doc_id、version、SHA-256 内容哈希、chunk index/ID、适用范围与有效期。UTF-8 BOM 和 CRLF 参与原内容哈希，不压缩或改写被引用原文。当前 5 文档、45 块。

英文/数字/下划线标识作为完整词，小写；连续中文拆单字与相邻双字。标题、章节与片段共同进入同一词频统计。BM25 使用 k1=1.2、b=0.75，去重查询词。先按宿主授权 doc_id、服务、环境和有效期过滤，再计算候选集合的词频、平均长度与分数；未授权内容不影响排名。一个文档多个有效版本时选择适用候选中最高 SemVer；失效版本不召回。相同分数按 doc_id/chunk index 稳定排序。

排名单位是块；默认 Top-3，上限 Top-5，同一文档可以占多名。score 是词法相似度，不是故障概率或因果置信度。仅 score>0 的块返回；无匹配为 `no_match` 和空 references。加载/查询错误不能冒充空结果。

宿主启动时最多 32 文档，单文档 64 KiB、manifest 32 KiB、总来源 512 KiB、最多 1024 块；标题最多 160 单元。工具查询最长 256 单元、输出最多 24 KiB、每宿主检索实例最多 16 次（有效失败也计数）；复用原 1 秒工具截止与取消信号。小规模同步打分只能在打分前后检查取消，不能中断 JavaScript 正在执行的单次 CPU 运算，因此还需上述规模上限。第 5 步可施加更窄的持久化 run 预算，本步不实现 Worker。

宿主显式给 Incident 绑定服务、环境与文档权限；工具参数只有 incident_id/query/top_k。支持严格 INC-三位数字与 LIVE-UUIDv4 的独立命名空间，不用于拼文件路径；只有已绑定 ID 能搜索。Agent 不能传服务、环境、URL、路径、版本或凭据来扩大范围。原 Pi Adapter 对额外参数可能先做 schema stripping；任何被剥离的字段均不成为来源，直接 handler 的 strict 校验也会拒绝它们。

## 知识与观测分别记录和显示

KnowledgeReference 是独立 strict DTO：reference/incident/run/tool-call ID、查询、doc/section/chunk、版本及内容/清单哈希、范围、位置、原片段、rank/score/retrieved_at、固定 purpose=investigation_guidance。每次重查生成新 reference_id，旧快照不被覆盖。

`incidentInvestigationContext` 明确返回 `observed_evidence` 与 `knowledge_references` 两个字段，以及“手册是调查指导、不是根因证据”的说明。只有真实取证走原 Evidence collector；引用不能进入原 Diagnosis.evidence_ids 或自动审批。CLI 显示同样两个类别，本步没有提前改第 6 步的 Console 页面。

ToolResult.payload.knowledge_result 记录完整返回快照，可以由既有 JsonlIncidentEvents 保存。`readRecordedKnowledge` 只解析历史数组，校验 Incident/run/query/tool-call 与引用范围；不读取手册、不按当前排名重算、不调用模型。原 Python Replay 可以接受此 payload 并维持合法状态、Evidence 与工具顺序校验；它仍显示原工具时间线，不把知识当 Evidence。本步新增历史知识投影供后续 Console 使用。

索引在当前宿主实例中不可变；更换手册需宿主重建新实例。更新文档应提高版本号，内容哈希同时精确区分内容；已记录的旧片段继续从事件读取。Markdown 与 manifest 是版本化源码，知识快照存现有事件。本步不新增 SQLite 表或改变 schema 70：计划中的 chunks/reference DB 持久化并入第 5 步调查任务事务，避免先建没有消费者的数据库存储；没有宣称 DB 查询/重启 Worker 已完成。

## 独立手工标注与限制

手册先独立完成，再写 [`evaluation/runbook-queries.json`](../evaluation/runbook-queries.json) 的手工 relevance 标签。16 条查询包含 12 条相关查询与 4 条期望空结果；涵盖中英词汇、错误服务/环境、无匹配、磁盘查询不能以池手册为第一名、过期/当前版本。已退休的 [`old-resource-pool.md`](../evaluation/runbook-review/old-resource-pool.md) 仅进入评测脚本自己的临时 review corpus，不进入线上清单。

评测脚本先建当前/历史两个索引，再读标注；不会按 expected_docs/expected_first 生成文档或答案。检索库和工具不导入评测脚本/标签。原 expected_cases.json、标准答案、case matrix 全部不参与此库。负例标签也不送进调查上下文。

本地实测 16/16 通过；12 条相关查询 Hit@3=12/12、Top-1=12/12、MRR@3=1，4 条空结果通过。统计在 Top-3 块内按不同文档匹配 relevance；不是取三个不同文档后补召回。数字仅证明这份小型、明确术语的人工查询集，未测大语料、隐藏 holdout、模糊自然语言泛化或线上诊断质量。

当前不支持 Setext 标题、完整 Markdown AST、复杂表格语义或跨节相邻块扩展。中文单/双字易出现同字噪声；英文形态、连字符、错别字、同义词和跨语言同义不自动等价。BM25 会偏向共享关键词和标题，Top-K 块可能重复同一文档；无匹配不证明没有适用手册，命中也不证明当前根因。版本有效期与服务标签依赖管理员维护，没有自动审核或线上更新分发。

本步已接工具与调查上下文、分开输出知识和观测、可记录与读历史；真实模型、Worker/DB 报告、浏览器 Console、生产 RAG 均未验收。完整测试结果与早期修复见 [进度记录](v0.3.0-progress.md)。第 4 步完成后停止，第 5 步须另行授权。
