人工 `/control/config` 仅修改本任务自己的资源槽服务；不注册为 Agent 工具，不制造 ActionExecuted。验证工具仅 `query_live_metrics`、`query_live_logs`，沿用 SAFE 门、预算、实际 ToolCalled/ToolResult/EvidenceCollected 或 ToolFailed。宿主加载已编译的 Runner 工具模块，保留现有两个编译根；先运行 Runner build。旧 Fixture 路径、格式和十二案例不变。

## 实际正常链路、工具和最终状态

1. 启动自有 loopback 演示服务，先取一份实际指标基线。受控故障配置为 capacity=1、hold_ms=180、acquire_timeout_ms=30、query_delay_ms=0；实际发出 6 个并发工作请求，产生 5 次资源获取超时、峰值等待 5。它是资源槽/连接池竞争演示，不是生产数据库。
2. 宿主有界阈值检测规则：同实例连续窗口中 `新增 acquire_timeouts >= 2 AND 峰值 pool_waiting >= 1`。低于阈值不生成告警；缺失、截断、错误范围/类型/时间窗或计数倒退不生成告警。实际指标触发后才构造归一化 DTO，通过专用带服务/环境 scope 的认证 Bearer 送入真实 Webhook HTTP 入口。不是人工填写成功告警，也不是已经接入实际 Alertmanager。
3. 同一投递并发发送 8 次，7 次重复、一个 Incident/活动任务；同故障窗口另一 external_id 聚合，最终 2 条告警/2 次有效投递。凭据越出环境返回 HTTP 403。原并发进程用例进一步证明数据库约束，不只依赖单进程 HTTP 排队。
4. 初次无模型 Worker 原子领取并实际调用 `query_live_metrics`、`query_live_logs`、`search_runbooks`：2 Evidence、3 KnowledgeReference、11 原事件，blocked / ESCALATED / no_configured_model。知识来源为五类通用 Markdown/BM25 手册，观测来自正在运行的服务；两类引用在 Console 分开。
5. 显式新调查由独立 CLI 进程重新打开同一独立 DB 领取；配置可取得。实际 real_pi 模型调用 1 次 HTTP 200，3 个宿主只读 preflight 工具调用，**没有模型发起的工具调用**；2 实际 Evidence、3 知识引用仍保存。模型最终报告被严格校验拒绝，宿主保存基于真实观测的升级结果；不伪造模型诊断或工具轨迹。没有为获取通过结果继续扩大预算。
6. 可信操作者仅恢复本任务演示配置：capacity=4、hold_ms=20、acquire_timeout_ms=500、query_delay_ms=0。记录 `manual_demo_restore/applied` 声明及时间；再发 8 次真实请求，8 成功、0 超时。
7. 宿主显式只读验证创建新 generation/run，以恢复时间为查询 from，重新调用 `query_live_metrics`、`query_live_logs`。2 新 Evidence、9 原事件、0 模型调用；相同完成请求重读记录，活动并发请求被拒绝，相同标识不同声明参数被拒绝。原故障/模型运行未改写。
8. 恢复观测检查全部通过：最近故障基线（两分钟内）、同实例/源/服务/环境、恢复后完整非空窗口（至少 100ms）、未截断/未丢失、计数单调、实际成功请求增量 8（要求至少 4）、新增超时/取消/溢出 0、最终 waiting=0 / active=0 / capacity=4、完成日志 8 / 失败日志 0。
9. **动作记录：人工演示恢复 applied；验证结果：verified；故障最终调查状态：ESCALATED / 需人工复核。** 没有合法处置状态链及人工根因复核，不宣布 RESOLVED。短窗口和八次演示请求只证明该范围观测恢复，不代表长期 SLO、根因证明或生产修复效果。
10. 停止自己的源后导出已存 JSONL，原 Python Replay 重建 ESCALATED、2 Evidence、0 执行动作。关闭重开独立 DB，再查完整记录等于原记录；浏览器只读回放同样不修改 run，不重新取证/检索/调用模型/审批。
