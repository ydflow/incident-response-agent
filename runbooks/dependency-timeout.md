# 依赖超时与下游调用失败

## 适用症状

依赖超时、下游 timeout、upstream timeout、HTTP 504、DNS 解析失败或 connection refused。多个调用方同时出现相同下游延迟时，应调查共享依赖；单个调用方故障也可能来自自身超时预算或连接复用问题。

## 补证据步骤

按服务、环境和调用窗口查看下游地址别名、超时类型、HTTP 状态、延迟分位数与 request_id。区分建连、读取、整体截止和取消；将调用方与下游的成功率、负载、队列长度交叉比较。优先补 Trace 跨服务时间线和网络观测；不可取得时只保留假设，不把通用手册当成现场因果证据。

## 处置前提与风险

确认依赖所有者、重试幂等性、熔断与回退语义。更改超时、重试、路由或降级开关需审批与回滚条件。盲目重试会放大故障负载，放宽截止可能占满调用方资源，回退可能改变业务结果。

## 恢复指标

同一调用路径的超时增量、错误率与延迟恢复基线；重试量没有继续增长，下游与调用方的资源使用率稳定。用新观测验证恢复，不仅查看探活成功。
