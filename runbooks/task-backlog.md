# 任务堆积与消费积压

## 适用症状

任务堆积、消息积压、queue backlog、consumer lag、oldest task age 上升。队列长度增加可能来自入口流量、消费者变慢、毒消息或重试放大，不能仅凭长度断言工作进程故障。

## 补证据步骤

按队列别名、服务和环境补入口速率、消费速率、任务年龄、成功/失败/重试增量与活跃消费者数。关联任务 ID 的领取、完成、租约过期与失败日志；检查下游依赖延迟和任务幂等约束。没有消息源权限时仅列出所需观测。

## 处置前提与风险

确认任务幂等、领取租约、死信策略、下游容量和顺序要求。扩消费者、暂停入口、重新投递或丢弃任务需审批。并发增加可能放大依赖压力，重复投递可能重复执行，清空队列可能造成业务丢失。

## 恢复指标

消费速率持续高于入口速率，oldest task age 和 queue backlog 下降，失败/重试不再增长，租约与完成计数一致。验证具体任务已完成，不能将队列被删除视为恢复。
